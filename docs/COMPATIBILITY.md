# XAMPP Compatibility Scope

기준일: 2026-09-04

이 문서는 XAMPP Updater가 어느 범위의 Windows XAMPP 설치를 안전하게 다룰 수 있는지 정리한 호환성 기준이다.
목표는 "모든 변형을 강제로 업데이트"하는 것이 아니라 **지원 가능한 설치를 자동 판별하고, 불확실한 설치는 실제 교체 전에 중단하거나 사용자 검토로 전환**하는 것이다.

## 현재 결론

현재 구현은 **일반적인 Windows XAMPP 디렉터리 구조를 사용하는 설치**를 범용 대상으로 삼을 수 있다.

기본적으로 다음 상대 경로를 기대한다.

- Apache: `apache/bin/httpd.exe`
- PHP: `php/php.exe`
- MariaDB: `mysql/bin/mysqld.exe` 또는 `mysql/bin/mariadbd.exe`

XAMPP 루트 자체는 `C:\xampp`로 고정하지 않는다. 수동 지정, 고정 드라이브의 `xampp` 후보, 제거 프로그램 레지스트리, Windows 서비스 `ImagePath`를 함께 사용해 찾는다.

## 이번 범용성 검토에서 확인/보강한 부분

### 설치 경로

- 임의 드라이브와 수동 지정 경로를 지원한다.
- 경로 결합은 `Path` API를 사용한다.
- 외부 프로세스 인수는 가능한 범위에서 `ArgumentList` 또는 개별 인수 형태로 전달한다.
- 공백/비 ASCII 문자가 포함된 경로를 설계상 허용한다.
- 쓰기 권한 또는 서비스 제어가 필요한 실제 작업은 필요한 시점에만 UAC 승격한다.

따라서 `D:\xampp`, `D:\Web Server\xampp`, 한글이 포함된 사용자 지정 경로도 **구조가 표준 XAMPP와 같다면 지원 대상으로 본다**. 다만 이러한 경로 조합은 별도 실제 환경 회귀 테스트 항목으로 유지한다.

### MariaDB 실행 파일 이름

기존 감지는 `mysql/bin/mysqld.exe`만 대표 실행 파일로 사용했다.

MariaDB 배포판/세대에 따라 서버 실행 파일 이름이 `mariadbd.exe`일 수 있으므로 다음 둘을 모두 감지 대상으로 사용한다.

- `mysqld.exe`
- `mariadbd.exe`

서비스 `ImagePath`에서 XAMPP 루트를 역추론할 때도 두 이름을 모두 허용한다.

### Windows 서비스

서비스 이름 자체를 `Apache2.4`, `mysql` 등으로 고정하지 않는다. 실제 서비스 `ImagePath`가 선택한 XAMPP 루트의 실행 파일과 일치하는지 기준으로 연결한다.

따라서 사용자 정의 서비스명도 원칙적으로 지원한다.

### 여러 XAMPP 설치

한 PC에 여러 XAMPP가 있어도 후보를 여러 개 수집할 수 있다. 실제 작업은 사용자가 선택한 단일 XAMPP 루트만 대상으로 한다.

다른 위치에 별도 설치된 MariaDB/MySQL은 관리 대상이 아니다.

## 지원 수준

### 지원

- Windows 11 x64
- 일반적인 XAMPP 폴더 구조
- XAMPP 루트의 임의 드라이브/수동 지정
- 서비스 등록된 Apache/MariaDB
- 사용자 정의 서비스명
- Apache/PHP/MariaDB의 설정 파일 수정 상태
- VirtualHost, SSL, 포트 변경 등 기존 설정 보존이 가능한 구성
- 외부 Apache 모듈 및 PHP extension이 존재하는 구성
  - 단, 기존 호환성/loader/runtime 검사를 통과해야 실제 업데이트 가능
- Apache/PHP/MariaDB가 시작/중지된 다양한 상태

### 조건부 지원

- 서비스 미등록 Apache
  - 실행 중이면 안전한 파일 교체를 위해 사용자가 먼저 종료해야 한다.
- 별도 실행 중인 `php.exe`
  - 실행 중이면 PHP 교체를 차단한다.
- 오래된 XAMPP
  - 구성요소 버전과 패키지 구조가 현재 검사 규칙에 의해 판정 가능해야 한다.
- x86 XAMPP
  - 감지와 일부 호환성 판정은 가능하지만, 현재 MariaDB 자동 후보는 공식 winx64 ZIP을 기준으로 하므로 전체 자동 업데이트 범위는 제한된다.
- `Program Files` 등 보호된 위치
  - 검사/비교는 일반 권한으로 가능하며 실제 쓰기/서비스 제어 시 UAC 승격이 필요하다.

### 미지원/범위 밖

- `apache`, `php`, `mysql` 디렉터리를 임의 이름/임의 위치로 재배치한 비표준 재패키징
- XAMPP 외부의 독립 Apache/PHP/MariaDB 설치
- Linux/macOS XAMPP
- Node.js, Perl, Tomcat, phpMyAdmin 등 이 프로젝트 범위 밖 구성요소
- 범용 DB 마이그레이션 도구로서의 사용

## 실제 환경 검증 이력

현재까지 다음 실제 업데이트 경로를 통과했다.

- Apache 2.4.41 → 2.4.68
- PHP 7.3.11 → 8.5.10
- PHP 8.2.12 → 8.5.10
- MariaDB 10.4.8 → 10.4.34
- MariaDB 10.4.34 → 10.6.28
- MariaDB 10.6.28 → 12.3.3
- Apache 설정 snapshot 실제 복원
- 배포 EXE 자체 업데이트 0.1.0 → 0.1.1

이 검증은 버전 폭에 대해서는 강하지만, 모든 설치 형태의 조합을 검증했다는 뜻은 아니다.

## 범용 회귀 테스트 매트릭스

향후 실제 사용자 환경 또는 테스트 VM이 확보될 때 아래 조합을 우선 확인한다.

| 구분 | 확인 항목 |
| --- | --- |
| 경로 | `C:\xampp`, `D:\xampp`, 공백 포함 경로, 한글 포함 경로, 보호된 위치 |
| 서비스 | 둘 다 등록, 둘 다 미등록, Apache만 등록, MariaDB만 등록, 사용자 정의 서비스명 |
| 상태 | 둘 다 실행, 둘 다 중지, 한쪽만 실행 |
| Apache 설정 | 기본, VirtualHost 다수, SSL, 포트 변경, 외부 모듈 |
| PHP 설정 | 기본, 수정된 php.ini, 외부 extension, PECL extension |
| MariaDB 설정 | 기본, 수정된 my.ini, 비기본 포트 |
| 세대 | PHP 7.x 기반 구형 XAMPP, PHP 8.0~8.2, 최근 세대 |
| 서버 실행 파일 | `mysqld.exe`, `mariadbd.exe` |

새 환경에서 문제가 발견되면 일반화된 추측으로 코드를 넓히기보다 **재현 가능한 실제 차이만 최소 수정**한다.

## 범용성 판정 원칙

1. 자동 감지 성공 여부와 실제 실행 가능 여부를 분리한다.
2. 알 수 없는 구성은 자동으로 "호환" 처리하지 않는다.
3. 기존 설정/모듈/확장의 실동작 검증 결과를 정적 추정보다 우선한다.
4. 파괴적 교체 전에는 반드시 롤백 백업과 사전 검증을 통과해야 한다.
5. 범위를 벗어난 비표준 구조는 억지로 지원하지 않고 이유를 표시한다.
